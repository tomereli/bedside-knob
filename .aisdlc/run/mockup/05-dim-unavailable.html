Two states that must not read the same

The card on the knob today prints OFF for anything whose state is not the string "on" — which means a light that is off and a light that has dropped off the Zigbee mesh look identical, and so does a light the knob has simply not heard about yet. Standing there turning a dial at a light that is not listening is the failure that produces.

—— in grey means no reading. OFF in amber means the light is genuinely off. One extra branch in the value lambda, and the two stop being the same picture.

This is beyond the issue's acceptance criteria and it is in this file on purpose, at a cost of one line, because the card it lands in is one this issue rewrites anyway.

Boot order: on_boot paints after 2 s and api.on_client_connected repaints 2 s after the connection, so this screen is what the first few seconds look like. Full offline treatment — telling him Home Assistant is unreachable rather than that a value is unknown — is REQUIREMENTS.md's ask and a separate issue.
